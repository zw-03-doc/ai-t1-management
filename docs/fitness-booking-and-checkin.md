# 课程、预约、签到与教练线索

## 关系

- 门店包含教练和课程。课程的默认教练必须属于同一门店且在职。
- 课程是内容与默认规则；排课是具体的北京时间开始/结束、门店、授课教练、名额及展示价格快照。修改课程默认值不追溯修改已有场次。
- 排课可以指定学员；存在指定名单时只有名单内会员可预约。名单为空时所有本租户会员可预约。场次名额由管理员配置，不再固定小班最多5人。
- 预约属于会员和具体场次，可关联线下办理的卡项。无卡会员也可预约开放场次并线下咨询教练；不会由前端请求直接付款或发卡。
- 训练计划与场次预约相互独立；练完计划不会自动产生课程签到，计划顺延不会挪动门店的排课。

## 日期规则

所有日历日期使用 `Asia/Shanghai`。

| 设置 | 含义 |
| --- | --- |
| `publishedAt` / `listingDays` | 上架起点与有效天数，后台计算 `listingUntil`；到期停止新预约和课程展示，已预约历史保留 |
| `bookingAdvanceDays` | 提前多少个日历日开始预约；0表示开课当天00:00，7表示开课日前7天00:00 |
| `reservationOpenTime` | 场次可单独覆盖的准确开放时间 |
| `bookingCloseMinutes` | 默认在开课前多少分钟截止预约，可被场次准确截止时间覆盖 |
| `cancelCloseMinutes` | 默认在开课前多少分钟截止会员取消 |
| `checkinBeforeMinutes` / `checkinAfterMinutes` | 开课前多少分钟至下课后多少分钟允许登记到场 |

开放时刻包含在窗口内，截止时刻不包含。草稿、关闭、取消、结束的场次不接受新预约。课程价格为人民币展示价，0表示免费；不连接支付系统。

同一教练的场次不能重叠；同一时段不同教练可上课。名额必须大于0且不小于已预约人数。已有预约时不能直接修改门店、课程、教练或开课时间，需先处理预约；有历史记录的课程与场次保留历史，通过下架/关闭管理。

## 签到和确认核销

沿用现有的两个业务步骤：

1. 会员主动签到或本场次教练代签到，产生到场记录。预约仍占用名额，禁止再取消。教练代签到必须填写原因，记录浏览器或小程序来源。
2. 教练或管理员确认核销后，预约变成 `signed`，`signedCount`增加1。如绑定卡项，则在同一事务中扣减课次/余额；无卡预约不扣权益。异常记录不能再次确认。

`checkinId=null` 表示尚未登记到场；有签到记录且 `operatorUserId=null` 表示待确认核销；已确认才有操作人。教练待办接口也返回尚未签到的预约，以便代签到。

会员ID与教练身份取自登录态，不能由客户端替换。本人签到和教练代签到锁定相同预约行；确认与异常处理同样串行，条件更新确保一次核销。预约同时使用场次行锁、原子名额更新、活动预约唯一键，取消后可以重新预约，不删除旧预约。

管理员的行为记录页记录操作者类型/姓名、会员、门店、场次、预约、签到、动作、来源、原因和服务器时间。业务操作与记录写入处于同一事务。后台课程、教练、排课的增删改继续由框架操作日志记录。

## 浏览兴趣与教练咨询

前端只在课程详情处于前台可见时累计时长，每次提交1至60秒增量；切后台和离开详情停止累计。事件ID防重，服务器按会员串行接收，并用实际流逝时间限制多标签页/多设备重复累计。

优先归属当前门店已绑定的在职教练，否则归属课程公开咨询教练。教练仅能看到分配给自己的近90天数据，且必须仍绑定此会员或仍担任该课程咨询教练；解绑后不会仅因历史分配获得查看权限。按会员、课程汇总有效浏览秒数、访问次数和最后访问时间。浏览时长表达可能兴趣，不代表确定购买意愿。

课程返回管理员填写的公开咨询微信号 `coachContactWechat`。教练的手机、激活码和内部账号信息不作为公开咨询资料返回。

## 微信及浏览器登录

- 微信登录必须提交 `wx.login` 的临时代码，由服务端换取真实身份；不接受客户端指定 `openid`。
- 教练浏览器使用已有账号密码登录接口，校验教练关联、在职状态和后台账号状态，按IP和账号限流。
- 会员在已登录设备生成128位随机网页登录码；120秒过期、Redis原子消费、只允许使用一次。浏览器通过POST提交，不放入URL。登录产生独立的web设备令牌。
- 微信真实登录需要有效的AppID/AppSecret和开发者/合法域名配置。网页登录码只能从已认证会员生成，不能代替微信身份验证。

## 数据迁移

按基线和V1.1.2之后执行 `V1.2.0_课程预约与行为.sql` 一次。可直接跳过旧V1.1.3（其脚本会删除重复记录）；新迁移也兼容已执行V1.1.3的数据库，会替换旧唯一索引。

对现有库先备份。若有重复活动预约或重复签到，新增唯一索引会明确失败，需人工核对历史；本迁移不会自动删除业务记录。数据库与Java进程应统一配置北京时间。

### 必需的教练身份角色

`V1.2.2_教练基础角色.sql` 补齐默认租户 `000000` 的 `jiaolian` 角色。旧V1.0.3只有注释中的插入示例，未真正创建该角色，会导致首次创建教练失败。

该角色固定ID为 `2042601000000001001`，状态正常，数据范围为 `5`（仅本人），没有后台菜单、部门或管理员授权，不修改租户套餐。创建教练时，已有Java业务将新教练账号绑定到此角色；教练浏览器和小程序功能继续由授课场次、所属门店、有效会员绑定关系控制，不需要给此角色授予整个管理后台权限。

迁移按 `tenant_id + role_key + del_flag` 判断是否已存在，重复执行不会新增第二条，也不会重启被管理员停用的已有角色。若固定ID被无关角色占用，会明确失败，需先核对ID。新增其他租户时应在该租户单独初始化同名角色，不复用默认租户角色。
