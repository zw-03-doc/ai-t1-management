## 发现并修复的问题

1. **初始密码超过登录接口上限。** 最初部署生成 32 字符密码，而管理员登录限制为 5–30 字符。改为 24 字符随机密码，同步数据库密码散列、教练初始密码配置与本地凭据，并通过正常管理员接口刷新配置缓存后，真实登录通过。
2. **新库缺少教练基础角色。** 新增教练时找不到 `jiaolian`。通过 `V1.2.2_教练基础角色.sql` 幂等补齐；真实临时库连续执行两次后均为单个正常角色、仅本人数据范围、无管理菜单权限，正式库应用后教练创建通过。
3. **框架表与旧业务表的租户列排序规则不一致。** 教练登录中的租户关联触发 MySQL 排序规则冲突。`V1.2.3_租户关联排序规则.sql` 将 14 个旧业务表的租户列统一为框架采用的 `utf8mb4_0900_ai_ci`。部署代理先完整备份并恢复至临时库双执行验证，再应用正式库；字段类型、空值约束、默认值、索引结构和数据行数保持，相关关联查询及真实教练登录均通过。
4. **媒体字节正确但响应 MIME 被预设为 JSON。** 首轮真实容器返回 PNG 字节，却使用 `application/json`。训练媒体控制器在权限检查成功后显式设置实际 MIME。新增响应类型回归测试，重新打包并仅更新 API 容器后，图片、视频和副本附件权限复测通过。MIME 可带可选参数；验收依据是实际媒体类型及字节一致性。

最终上线 API 为 r3 构建，JAR SHA-256：`8d9fa387cbde1bf5e81e7ff4a1f6ede05fb1154750cf5f13020b7d67e10e77de`。
