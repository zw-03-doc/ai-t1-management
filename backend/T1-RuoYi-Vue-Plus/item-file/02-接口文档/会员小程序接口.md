## 荆州市某健身房项目第一阶段会员微信小程序接口文档

### 一、文档说明
本文件面向 **会员微信小程序端**，用于沉淀当前一期会员端后端接口的真实实现口径。

当前代码位置：
- `ruoyi-system/src/main/java/org/dromara/fitness/controller/FitnessMiniController.java`
- `ruoyi-system/src/main/java/org/dromara/fitness/service/impl/FitnessMiniServiceImpl.java`
- `ruoyi-system/src/main/resources/mapper/fitness/FitnessMiniMapper.xml`

推荐前缀：`/fitness/mini`

### 二、当前实现边界
#### 1. 已落地范围
当前已落地的会员端能力包括：
- 登录与手机号绑定
- 首页聚合
- 门店列表与门店详情
- 课程列表与课程详情
- 可预约排课列表
- 课程预约、我的预约、取消预约
- 卡项列表、卡项详情
- 创建订单、订单列表、订单详情
- 我的会员权益
- 发起签到、查询签到状态、我的签到记录
- 我的摘要、编辑个人资料

#### 2. 当前兼容实现说明
- 当前登录入参使用 `code`（小程序 `wx.login()` 返回），后端通过微信 `code2Session` 接口换取 `openid` 后自动注册/自动登录；兼容保留 `openid` 直传方式。
- 当前手机号绑定入参使用 `phoneCode`（微信手机号授权临时 code），后端解密后回填手机号。
- 当前订单为一期兼容实现，支持基础购卡下单与发卡。
- 当前签到状态由接口层推导，不直接等同数据库原始值。

### 四、鉴权与响应约定
#### 1. 鉴权方式
除 `wechatLogin` 外，其余接口统一使用：
- `Authorization: Bearer {memberToken}`

#### 2. 通用响应结构
- **单对象**：`R<T>`
- **分页列表**：`TableDataInfo<T>`
- **动作类**：`R<Void>` 或 `R<T>`

#### 3. 当前签到状态口径
| 条件 | 返回状态 |
| --- | --- |
| 尚无签到记录 | `not_checkin` |
| 已签到，教练未处理 | `pending_confirm` |
| 教练已确认 | `confirmed` |
| 教练标记异常 / 已撤销 | `exception` |

### 五、核心接口整理
#### 1. `POST /fitness/mini/auth/wechatLogin`
- **说明**：会员登录接口，使用微信 `code` 登录。前端调用 `wx.login()` 获取 `code` 后传入，后端通过微信 `code2Session` 换取 `openid` 后自动注册或更新 `fit_member`
- **主要表**：`fit_member`

##### 请求体字段
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `string` | 是 | 小程序 `wx.login()` 返回的临时 code，通过微信 `code2Session` 接口兑换 `openid` |
| `phoneCode` | `string` | 否 | 微信手机号授权返回的临时 code |
| `openid` | `string` | 否 | 兼容旧链路的直传 openid |
| `unionId` | `string` | 否 | 微信 unionId |
| `nickname` | `string` | 否 | 昵称 |
| `avatarUrl` | `string` | 否 | 头像 |
| `realName` | `string` | 否 | 真实姓名 |
| `mobile` | `string` | 否 | 手机号 |
| `homeStoreId` | `long` | 否 | 归属门店 |
| `remark` | `string` | 否 | 备注 |

##### 响应字段摘要
- `accessToken`
- `expireIn`
- `clientId`
- `openid`
- `memberInfo`
  - `tenantId`
  - `memberId`
  - `memberNo`
  - `homeStoreId`
  - `mobile`
  - `realName`
  - `nickname`
  - `avatarUrl`
  - `memberStatus`

#### 2. `POST /fitness/mini/auth/bindPhone`
##### 请求体字段
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `phoneCode` | `string` | 是 | 微信手机号授权返回的 code，由后端解密手机号 |

### 六、前后端联调提示
- 小程序页面骨架已存在，但当前页面仍主要是展示态和 mock 视图。
- 当前会员登录真实口径为：前端调用 `wx.login()` 获取 `code`，后端换取 `openid` 后自动注册/自动登录；前端不再把 `phoneCode` 作为登录前置条件。
- 当前手机号绑定独立走 `bindPhone`，前端需要在确有授权能力时单独触发。
- 当前教练确认核销后，会员侧看到的状态主要通过 `derivedCheckinStatus` 判断。
- 若后续接入真实支付、活动中心，需要单独开第二轮接口整理。
