二、项目背景
荆州市某健身房计划建设一套“PC 后台管理系统 + 会员微信小程序 + 教练 App 端”，用于支撑健身房日常经营管理、会员服务、课程预约、私教管理、门店运营及后续多门店、多商户发展。

当前业务痛点主要包括：
1. 会员信息、购卡信息、课程记录、教练信息分散管理，数据统计困难。
2. 门店运营数据缺乏统一沉淀，无法实时掌握会员增长、消课、续费、私教销售等经营情况。
3. 会员端服务能力不足，学员无法便捷完成课程预约、签到、购卡、查看剩余课次等操作。
4. 教练端缺少移动化工作台，无法高效接收签到信息、确认私教课核销、查看本人排课和学员情况。
5. 后续若发展连锁门店或多商户合作模式，缺少统一的平台化管理能力。

因此，需建设一套以 PC 后台管理为经营核心、以微信小程序为会员入口、以教练 App 为私教核销入口、兼顾后续扩展能力的数字化管理系统。

三、项目建设目标
1. 建立统一的会员、门店、教练、课程、订单、卡项、签到、核销、财务数据管理体系。
2. 支持健身房业务在线化，提升门店运营、教练带课、会员服务效率。
3. 为会员提供小程序端服务能力，实现在线购卡、预约课程、查看权益、签到等功能。
4. 为教练提供 App 端服务能力，实现移动查看排课、接收学员签到、确认私教课核销、查看学员信息等功能。
5. 支持后续多门店、连锁经营、多商户入驻等业务扩展。
6. 建立基础报表分析能力，为经营决策提供数据支撑。

四、项目定位
本项目定位为“健身房三端协同业务管理与会员服务平台”，初期服务于荆州市某健身房，后续预留发展为连锁健身房/多商户平台的能力。

五、项目范围
（一）本期建设范围

2. 微信小程序端用户系统

5. 多端商城复杂分销体系

六、业务模式假设
为便于系统设计，当前先做如下业务假设：
1. 健身房可存在一个或多个门店。
2. 一个会员可归属于某个主门店，也可在授权范围内跨门店消费。
3. 健身房存在普通团课、精品小班课、私教课等课程类型。
4. 销售模式包含次卡、月卡、季卡、年卡、储值卡、私教课包等。
5. 后续可能存在多个商户/品牌入驻，因此系统需具备多租户或多商户扩展能力。
6. 微信小程序作为会员端主要入口，PC 后台作为运营管理主平台，教练 App 作为教练移动工作台。


七、系统用户角色
（一）平台侧角色（预留）
1. 平台管理员：负责平台级商户管理、租户管理、基础配置、平台运营数据查看。

（二）商户/门店侧角色
1. 商户管理员：负责本商户整体配置、门店管理、员工管理、会员规则、课程规则、经营数据查看。
2. 门店店长：负责本门店运营管理、排课、会员管理、订单核销、报表查看，并查看教练核销执行情况。
3. 前台/会籍顾问：负责会员接待、办卡、续费、订单录入、到店异常处理、基础售后。
4. 教练：通过教练 App 查看课程安排、会员信息、学员签到结果、执行私教课核销/确认、跟进学员上课情况。
5. 财务/运营人员：查看订单流水、收支情况、经营分析。

（三）用户侧角色
1. 普通会员：注册、登录、购卡、预约、签到、查看课程和个人账户。
2. 潜在客户：浏览门店、课程、教练、活动信息，提交咨询或体验预约。

八、总体业务流程概述
1. 用户通过微信小程序注册/授权登录。
2. 用户浏览门店、课程、教练、卡项信息。
3. 用户在线购买会员卡、课包、私教课程或提交体验预约。
4. 用户预约课程或私教课，到店后在小程序发起签到并生成签到凭证。
5. 教练在自己的 App 中接收学员签到结果，确认到课情况并完成私教课核销/消课。
6. PC 管理端同步记录会员档案、订单流水、签到记录、核销记录、教练服务记录。
7. 管理端统计门店经营情况、会员增长、续费率、消课情况等数据。


九、核心功能需求

（一）PC 后台管理系统需求

1. 登录与权限管理
1.1 支持账号密码登录。
1.2 支持按角色进行菜单权限、按钮权限、数据权限控制。
1.3 支持不同门店、不同岗位查看各自授权数据。
1.4 支持操作日志、登录日志记录。

2. 首页工作台/经营驾驶舱
2.1 展示今日到店人数、今日新增会员、今日销售额、今日消课数。
2.2 展示本月会员增长、续费情况、课程预约情况、私教销售额。
2.3 支持按门店查看经营看板。
2.4 支持查看待处理事项，如待开卡、待核销、待跟进会员、待上课课程。

3. 商户与门店管理
3.1 支持商户信息管理（为后续多商户预留）。
3.2 支持门店新增、编辑、启用/停用。
3.3 支持维护门店地址、联系方式、营业时间、门店图片。
3.4 支持设置门店可售卡项、课程、教练归属关系。

4. 组织架构与员工管理
4.1 支持岗位、部门、员工账号管理。
4.2 支持员工与门店绑定。
4.3 支持员工角色分配，如店长、前台、会籍、教练、运营。
4.4 支持员工状态管理、重置密码、账号停用。

5. 会员管理
5.1 支持会员档案管理，包括姓名、手机号、性别、生日、来源渠道、所属门店等。
5.2 支持会员标签体系，如新客、潜客、活跃会员、流失会员、私教会员等。
5.3 支持会员余额、卡项、课包、积分、优惠券等权益查看。
5.4 支持会员跟进记录、回访记录、备注信息维护。
5.5 支持按门店、标签、会员状态筛选查询。

6. 教练管理
6.1 支持教练档案维护，包括资质、擅长项目、简介、头像、所属门店。
6.2 支持教练排班管理。
6.3 支持教练课时统计、带课统计、会员评价查看。
6.4 支持教练与课程绑定。

7. 课程管理
7.1 支持课程分类管理，如团课、私教、小班课、体验课。
7.2 支持课程基础信息配置，包括课程名称、时长、人数上限、封面、简介、适合人群。
7.3 支持课程与门店、教练、卡项的关联配置。
7.4 支持课程上下架。

8. 排课管理
8.1 支持按教练、门店、日期维度排课。
8.2 支持设置课程时间、可预约人数、候补人数。
8.3 支持课程调整、取消、补课。
8.4 支持查看课程预约名单和到课情况。

9. 预约与签到管理
9.1 支持会员预约课程。
9.2 支持后台代客预约。
9.3 支持查看签到、取消签到、请假、缺席等状态管理。
9.4 支持查看会员小程序签到结果、教练 App 核销结果与异常状态。
9.5 支持签到记录、消课记录查询。

10. 卡项与商品管理
10.1 支持会员卡管理：次卡、月卡、季卡、年卡、储值卡等。
10.2 支持私教课包管理。
10.3 支持商品管理，如饮品、运动周边、附加服务。
10.4 支持设置售价、有效期、使用规则、适用门店。
10.5 支持上下架与库存配置（如有实物商品）。

11. 订单与收银管理
11.1 支持办卡、续费、充值、购课、商品购买等订单录入。
11.2 支持线上订单与线下订单统一管理。
11.3 支持订单支付状态管理。
11.4 支持退款、撤销、售后记录。
11.5 支持按门店、时间、订单类型统计。

12. 会员权益与账户体系
12.1 支持会员卡状态查询。
12.2 支持剩余课次、有效期、余额、冻结状态管理。
12.3 支持会员卡启用、停用、冻结、延期、转卡等业务（可分阶段实现）。
12.4 支持私教课包消耗记录查询。

13. 营销管理（基础版）
13.1 支持发布活动，如新客体验、节日优惠、续费优惠。
13.2 支持优惠券、满减、折扣等基础营销能力。
13.3 支持活动海报上传与展示。
13.4 支持活动报名或体验预约。

14. 消息通知
14.1 支持预约成功、预约取消、上课提醒、到期提醒等通知。
14.2 支持后台消息公告发布。
14.3 支持小程序订阅消息、App 站内消息能力（后续可扩展短信）。

15. 文件与素材管理
15.1 支持图片、头像、课程封面、海报、门店图等文件上传。
15.2 文件统一存储到对象存储服务。
15.3 支持按业务分类管理文件。
15.4 支持文件预览、删除、替换。

16. 报表统计
16.1 会员报表：新增会员数、活跃会员数、流失会员数、会员来源分析。
16.2 销售报表：办卡金额、续费金额、私教销售额、商品销售额。
16.3 课程报表：课程预约率、到课率、缺席率、取消率。
16.4 教练报表：带课次数、服务人数、好评情况、课时收入。
16.5 门店报表：门店营收、门店会员数、门店教练绩效。

17. 系统设置
17.1 支持基础字典配置。
17.2 支持门店基础参数配置。
17.3 支持上传配置、对象存储配置。
17.4 支持小程序与教练 App 相关配置（AppID、消息模板、登录参数等，后续接入时配置）。

十、多门店与多商户扩展需求
1. 支持一个商户下多个门店统一管理。
2. 支持不同门店独立管理课程、教练、会员、订单。
3. 支持平台管理员查看全局数据，商户管理员仅查看本商户数据，门店角色仅查看本门店数据。

5. 支持按租户/商户维度进行配置隔离、对象存储隔离、业务数据隔离。
6. 支持平台级套餐、商户账号、功能授权的后续扩展。

十二、业务规则建议
1. 会员手机号应作为重要识别字段，避免重复建档。
2. 预约课程时需校验会员卡/课包是否可用、是否在有效期内。
3. 课程名额满员后支持候补机制（可选）。
4. 用户取消预约需遵守门店设置的时间规则。
5. 学员在小程序签到后，系统需生成待确认记录，由教练 App 完成私教课核销或异常处理。
6. 私教课程需支持按教练、会员、课包维度统计。
7. 门店数据原则上隔离查看，但允许商户管理员跨门店汇总查询。
8. 教练核销完成后，系统需同步更新预约状态、消课记录、会员权益与教练服务记录。

十三、非功能需求

1. 性能要求
1.1 支持日常门店业务稳定运行。
1.2 常用页面响应时间原则上不超过 3 秒。
1.3 支持课程预约高峰时段并发访问。
1.4 支持教练 App 在移动网络场景下稳定查看排课与执行核销。

2. 安全要求
2.1 后台账号需支持权限控制、密码管理、日志审计。
2.2 用户敏感信息需做好脱敏与安全存储。
2.3 接口需具备鉴权、限流、防重复提交等能力。
2.4 文件上传需限制类型、大小，并具备访问控制能力。
2.5 教练 App 需限制仅访问本人相关排课、学员与核销数据。

3. 可扩展性要求
3.1 支持从单门店扩展到多门店。
3.2 支持从单商户扩展到多商户。
3.3 支持后续接入支付、短信、企业微信、智能门禁等外部能力。
3.4 支持后续扩展更多教练端移动能力，如跟课记录、课后点评、绩效展示等。

4. 运维要求
4.1 支持日志查看与异常排查。
4.2 支持数据库备份与恢复。
4.3 支持对象存储资源管理。
4.4 支持系统参数配置与环境部署。

十四、阶段性建设建议

第一阶段（最小可用版本）
1. 账号与权限
2. 门店管理
3. 会员管理
4. 教练管理
5. 课程与排课
6. 预约与签到闭环
7. 卡项与订单
8. 微信小程序登录、首页、预约、签到、我的
9. 教练 App 登录、首页、排课、待核销、学员、我的
10. 文件上传与基础报表

第二阶段（经营增强）
1. 营销活动
2. 优惠券
3. 教练绩效
4. 会员回访与标签运营
5. 更多经营报表
6. 教练端课后点评、训练记录等增强能力

第三阶段（平台化扩展）
1. 多商户入驻
2. 商户套餐管理
3. 平台级运营管理
4. 更多第三方能力集成

十五、验收重点建议
1. 会员建档、办卡、购课、预约、小程序签到、教练 App 核销流程是否完整可用。
2. 门店、课程、教练、卡项、订单、签到、核销数据是否能形成闭环。
3. 小程序端是否能完成登录、浏览、预约、签到、查看个人权益等核心动作。
4. 教练 App 是否能完成登录、查看排课、处理待核销私教课、查看本人学员等核心动作。
5. 数据权限是否符合平台、商户、门店、教练不同角色要求。
6. 文件上传、图片展示、对象存储访问是否正常。
7. 报表数据是否能反映真实经营情况。

十六、结论
本项目建议以“PC 管理端 + 会员微信小程序 + 教练 App”三端协同为核心目标，采用可扩展架构，先满足当前荆州市某健身房的经营需求，同时预留连锁门店、多商户平台化发展的能力。当前系统建设应以业务闭环、运营效率、会员体验、教练执行效率为优先，在保证核心流程跑通的基础上逐步扩展高级能力。
